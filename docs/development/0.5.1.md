# 0.5.1 Development Notes

## Scope

0.5.1 is the package-surface replacement for the withdrawn 0.5.0 Registry
archive. It retains the validated 0.5.0 frontend maintenance behavior and adds
the package correction merged in PR #127. Open follow-up boundaries in Issues
#54, #55, and #56 remain maintenance backlog and are not implied complete by
this release.

## User-Visible Fix

- The Registry package now includes `web/js/autocomplete/` and every local
  module statically imported by the Autocomplete entry module.
- Users who installed 0.5.0 must update to 0.5.1 or later, restart ComfyUI, and
  hard-refresh the browser. The 0.5.0 archive could still load tag tooltip data
  while failing to open typed suggestion lists because the controller modules
  were absent.

## Package Contract

- Package version: `0.5.1`
- Plain-text changelog: `.github/registry/changelogs/0.5.1.txt`
- Maintained release workflow metadata: `package_version=0.5.1`
- The package regression follows the Autocomplete entry module's
  repository-local static relative imports recursively. Every resolved file
  must exist, be Git tracked, and remain included by `.comfyignore`.
- The deleted 0.5.0 Registry version is not listed as a current metadata sync
  target and must not be republished.

## Validation

- Frozen hotfix production checkpoint: Python unittest 400/400, 104 frontend
  JavaScript files, TypeScript 6.0.3, and diff checks.
- `comfy node validate` passed. An actual 0.5.1 `comfy node pack` archive
  contained all 138 expected files, reported package version 0.5.1, and
  included the complete eight-file Autocomplete local import closure. Final
  published asset digests are recorded only after exact-`main` read-back.
- The extracted package was served by the Codex test instance. Legacy canvas
  and Node 2.0 each passed typed input, suggestion display, keyboard selection,
  Escape close, and workflow save/reload, with no relevant module or 404 errors.
- Release preparation changes metadata and documentation only. Do not repeat
  full or browser validation unless production code or its tested base changes.

## Release And Rollback

- Create a new annotated `v0.5.1` tag and new GitHub/Registry release from the
  protected `main` merge. Never move or reuse `v0.5.0`.
- After the replacement is independently downloadable and verified, withdraw
  the public 0.5.0 GitHub Release/tag. The Registry 0.5.0 version is already
  deleted.
- If 0.5.1 must be rolled back, use protected PRs and publish a new patch
  version; never replace an existing Registry payload in place.
