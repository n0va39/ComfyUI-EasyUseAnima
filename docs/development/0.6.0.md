# 0.6.0 Development Notes

## Scope

0.6.0 is the backward-compatible minor release for the advanced AiO integration
queue tracked by Issues #409, #410, and #411. It adds stage-aware model patch
ownership, environment-guided Torch Compile settings, and ComfyUI-ppm NegPip
Off, On, and Turbo modes.

The release keeps existing node identifiers, public sockets, workflow schemas,
saved prompts, and stored CFG values compatible. Release preparation changes
metadata and maintained workflow package-version fields only; it does not change
production JavaScript or Python.

## User-Visible Changes

- DAVE can use independent first-pass, Highres, Detailer, and Upscale stage
  scopes. Existing workflows retain the previous all-stage behavior.
- Safe PAG and SageAttention stage scopes remain unsupported candidates rather
  than being silently treated as partial stage support. FP16 accumulation and
  Torch Compile remain run-wide under the current upstream contract.
- AiO Advanced settings expose bounded KJNodes and Torch environment diagnostics
  and a recommendation action that preserves unrelated user settings.
- Known variable-size stages constrain the Torch Compile recommendation so it
  does not opt into incompatible shape assumptions.
- NegPip Off preserves the original model and conditioning path, On invokes the
  public ComfyUI-ppm adapter once, and Turbo applies the reviewed negative
  inversion and neutral-negative conditioning contract.
- Turbo uses effective CFG 1 only for the first pass, Highres, Detailer, and
  USDU sampling stages. Saved prompts and per-stage CFG values remain unchanged,
  and ResShift, postprocess, and save do not receive a sampling override.

## Compatibility And Rollback

- Existing workflows load NegPip as Off and preserve previous model-patch
  behavior unless a supported stage scope is explicitly selected.
- Unknown or incompatible model-patch scopes and malformed NegPip results are
  fail-closed.
- Public node identifiers, socket ordering, workflow schemas, stored prompts,
  stored CFG values, profiles, and settings formats remain compatible.
- The 0.6.0 release-prep commit is metadata-only and can be reverted before
  publish without reverting the validated production features.
- After publish, neither the Registry payload nor tag is rewritten. A correction
  uses a later patch version.

## Release Boundary

- Release target: protected `dev` to `main` promotion followed by annotated tag
  `v0.6.0`, GitHub Release, Registry publish, metadata sync, and live Registry
  read-back.
- Promotion uses the exact reviewed release-prep tree. A tree mismatch stops the
  release rather than being corrected after tagging.
- The next implementation queue is re-evaluated only after publication,
  Registry read-back, and immediate regression review are complete.
