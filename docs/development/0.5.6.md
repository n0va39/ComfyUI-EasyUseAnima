# 0.5.6 Development Notes

## Scope

0.5.6 is the patch release for the queue-result and seed UI regressions tracked
by Issues #413, #414, and #415. It prevents completed executions from replacing
newer editable state while preserving the execution history needed for the next
intentional queue.

The release keeps the existing node, workflow, profile, settings, and public API
contracts. It does not resume the deferred backend or advanced integration
roadmaps.

## User-Visible Changes

- LoRA Preset no longer replays an executed profile over the user's current
  profile or calls profile save for a stale result.
- Prompt Studio Classic, Extend, Advanced, and AdvancedV2 preserve current field
  values when an older, duplicate, ambiguous, or disposed result arrives.
- Prompt Studio Wildcard publishes a concrete next seed only for the current
  edit revision and updates only its narrow seed view.
- AiO special selections `-1`, `-2`, and `-3` remain editable workflow intent;
  the concrete executed seed is recorded separately as Last Seed.
- AiO concrete after-generate updates are compare-and-commit operations. Newer
  user edits win, while Use Last and New Fixed Random explicitly create a
  concrete fixed selection.
- Returning to a concrete AiO seed after a special stream starts from the value
  the user entered instead of continuing stale reservation state.

## Compatibility And Rollback

- Existing workflows keep special seed tokens and their stored control values.
- Public node identifiers, socket ordering, workflow schemas, settings, profiles,
  and API payload contracts remain compatible.
- The 0.5.6 release-prep commit is metadata-only and can be reverted before
  publish without reverting the validated production fixes.
- After publish, neither the Registry payload nor tag is rewritten. A correction
  uses a later patch version.

## Release And Resume Boundary

- Release target: protected `dev` to `main` PR followed by annotated tag
  `v0.5.6`, GitHub Release, Registry publish, metadata sync, and live Registry
  read-back.
- `main` merge, tag, release, and Registry publication require final user
  approval after the release-prep PR is merged to `dev`.
- The advanced integration queue remains frozen until publication/read-back and
  immediate regression review are complete.
