# 0.5.5 Development Notes

## Scope

0.5.5 is the release-first stabilization checkpoint integrated on `dev` after
0.5.4. It completes the user-visible release lane tracked by Issue #395:
cross-user LoRA profile provenance, LoRA profile scrollbar interaction,
locale-aware autocomplete initialization, Prompt Studio resolution swapping,
long-paste growth, and the four-part autocomplete editing contract.

The package remains on the 0.5 line by explicit project decision while broader
feature development and backend refactoring continue. Although this release
contains backward-compatible UI additions that would normally select a minor
version under `MAINTAINING.md`, 0.5.5 is treated as the bounded stabilization
release for the existing 0.5 user surface. It does not introduce breaking node,
workflow, settings, profile, or API contracts.

## User-Visible Changes

- Shared LoRA workflows report a profile as saved only when the current local
  profile store contains the same identity and content.
- LoRA profile scrollbars accept track clicks and thumb drags on Legacy Canvas
  and Node 2.0.
- Prompt Studio Classic, Extend, Advanced, and AdvancedV2 grow after long paste
  layout without shrinking a newer revision.
- A fresh Korean locale chooses the Korean autocomplete source only when no
  explicit source exists. Existing source choices remain authoritative.
- Advanced and AdvancedV2 resolution controls swap width and height for exact
  inverse presets and custom values while keeping NAIA fallback behavior safe.
- Artist autocomplete supports a configurable prefix with `@` parity by
  default.
- Mid-text completion separates query, insert, replace, and protected-suffix
  ranges so adjacent text, weights, and closing syntax survive commits.
- Selected prompt text can be wrapped with `()`, `{}`, or `[[ ]]`; an optional
  setting inserts `(selection:1)` and selects the numeric weight.

## Compatibility And Rollback

- Existing workflows, settings, profiles, node identifiers, socket ordering,
  and API payloads are preserved.
- New settings use prior behavior as their default and do not migrate or
  rewrite existing user values.
- The 0.5.5 release-prep commit is metadata-only and can be reverted before
  publish without reverting the validated `dev` implementation range.
- After publish, neither the Registry payload nor tag is rewritten. A release
  correction uses a later patch version.

## Release And Resume Boundary

- Release target: protected `dev` to `main` PR followed by annotated tag
  `v0.5.5`, GitHub Release archive, Registry publish, metadata sync, and live
  Registry read-back.
- D/E/G/H and AiO Hook implementation remain frozen until tag, GitHub Release,
  Registry publish/read-back, and immediate regression review are complete.
- After 0.5.5, resume from the then-current `dev` import graph and open issues;
  do not reuse a stale pre-release refactor task automatically.
