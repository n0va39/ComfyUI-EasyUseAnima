# 0.5.0 Development Notes

> **Withdrawn package:** the 0.5.0 Registry archive omitted required
> `web/js/autocomplete/` runtime modules. Use 0.5.1 or later. The notes below
> remain as the historical maintenance checkpoint; they are not an install
> recommendation.

## Scope

0.5.0 is the frontend maintenance and queue-state reliability release after
0.4.0. It packages the validated maintenance work merged after the 0.4.0 tree
alignment checkpoint. Open follow-up boundaries in Issues #54, #55, and #56
remain maintenance backlog and are not implied complete by this release.

## User-Visible Changes

- Stabilized rapid consecutive queue seed ownership for native Wildcard and
  Regional Prompt Studio queues, and for Advanced queues including nodes inside
  attached subgraphs.
- Unified public/edit/next Wildcard seed behavior at the JavaScript-safe range
  `0..9007199254740991`, while preserving loaded legacy Python `uint64` seeds.
- Hardened AiO Generator queue transactions, extension re-entry, sampler
  hydration, native preview, settings dialogs, profiles, panel rendering,
  resize, and scroll lifecycle ownership.
- Hardened Autocomplete IME, keyboard, popup, and request/source epoch behavior
  so stale or failed results cannot overtake the latest source or query.
- Hardened LoRA Preset menu, preview, and canvas widget lifecycle cleanup,
  including folder-label escaping and idempotent install/dispose behavior.
- Split the maintained frontend into smaller lifecycle and pure-data modules
  without changing public node names, workflow serialization, or API routes.

## Compatibility

- Existing node names, workflow JSON contracts, API routes, and saved AiO
  generation settings remain compatible.
- Loaded legacy Python `uint64` Wildcard seeds remain preserved. New edits use
  the JavaScript-safe integer range documented in the wildcard guides.
- Legacy canvas and Node 2.0 remain supported frontend surfaces.
- Open follow-ups #62, #66, #98, #100, and #111 are not part of this release.
