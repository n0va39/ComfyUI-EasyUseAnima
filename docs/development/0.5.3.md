# 0.5.3 Development Notes

## Scope

0.5.3 is the patch release for the backend maintenance integrations and the
wildcard reproducibility fixes already integrated on `dev`. It preserves the
existing public node, workflow, settings, profile, and API contracts.

## User-Visible Changes

- Anima Wildcard uses the Impact Pack-compatible wildcard and dynamic-prompt
  rules, expands file wildcards such as `__samples/flower__`, and exposes the
  filled text used for generation.
- Wildcard and Prompt Studio results are deterministic for the same seed.
  Fixed, randomize, increment, normal, sequential, and previous-seed reuse
  paths preserve the intended result.
- Loading a saved workflow keeps its wildcard seed fixed so the saved expanded
  prompt can be reproduced.
- The Wildcard Seed dialog presents concise seed controls and moves the full,
  readable rule reference behind its information button.
- Profile and settings persistence, Autocomplete indexing and request handling,
  prompt translation, and API error reporting are more reliable.

## Package Contract

- Package version: `0.5.3`
- Plain-text Registry changelog:
  `.github/registry/changelogs/0.5.3.txt`
- Maintained release workflow metadata: `package_version=0.5.3`
- Registry 0.5.2 remains an immutable published version and is not overwritten
  or reused.

## Validation

- The release candidate uses the official full project runner plus
  `comfy node validate` and an actual `comfy node pack` archive inspection.
- The exact pre-release `dev` checkpoint passed 727 Python unittests, 112
  frontend JavaScript smoke files, TypeScript 6.0.3, and diff checks.
- Wildcard file expansion, equal-seed determinism, prior-seed reuse, saved
  workflow fixed-seed behavior, and seed-dialog behavior have focused
  regression coverage.
- Legacy canvas and Node 2.0 browser checks were completed for the final
  wildcard production tree before the release metadata slice.

## Included Maintenance Range

- Post-0.5.2 backend and frontend maintenance integrated through PR #225.
- Wildcard compatibility and reproducibility fixes integrated through PR #233.
- Release preparation changes only version, changelog, Registry metadata,
  workflow package metadata, release notes, and this development checkpoint.

## Release And Rollback

- Release target: protected `dev` to `main` PR followed by annotated tag
  `v0.5.3`.
- Publish only after the tag resolves to the released `main` commit.
- If a release fix is needed, publish a later patch version. Never replace the
  0.5.3 Registry payload or rewrite its public tag.
